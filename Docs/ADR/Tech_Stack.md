# {Chosen Technology stack}

## Deciding what technology stack to use for proof-of-concept

For my proof-of-concept application, I need to identify what technology stack and tools I am going to use to create the system. The chosen tech stack needs to be ideally familiar and fairly easy to use, yet widely extensible so that appropriate features can be implemented in the future. I have chosen to create a website therefore, my chosen tech stack must align with this.

## Considered Options

*1. {Traditional -- HTML/ CSS (frontend) | PHP (backend) | MySQL (database)}
    - using php is perfect/ ideal for small- medium apps -- this suites my website needs

*2. {MERN -- React (frontend) | Node.js/ Express.js (backend) | MongoDB (database)}
    - MongoDB not as good as storing bank user data as MySQL
    - data classes can often contain diff types of data in MongoDB

*3. {Large-scale -- React/Angular (frontend) | Java/ Spring Boot (backend) | PostgreSQL (database)}
    - react/ angular | Java/ spring boot used with large scaled apps - i'm creating proof of concept
    - I don't need to have complicated UI- only simple
    - spring boot is Java framework for microservices/ web apps -- im not creating microservices or using microservices Arc style
    - spring boot is better for larger teams -- not individual

## Decision Outcome

Chosen option: "Traditional", because I am already most familiar with using that technology stack so this route would not take long at all for me to adapt into my proof-of-concept, meaning it is the most appropriate approach for me. Additionally, the MERN stack is not as good as MySQL when storing data for bank users, and the large scale tech stack is, given the name, better off for larger applications and easier to control in a lare team. Considering all of this, this means that the traditional tech stack just makes the most sense for me.

### Consequences

Good

* Good, because the traditional tech stack approach is simple, easy to use, familiar and I already have experience with these languages. The final outcome was positive as I managed to create a functioning proof-of-concept application which included all of the features I needed in order to fulfil my client requirements.

Bad

* Bad, because if I had used alternative languages/ tech stacks, I would have been able to create a system with far greater capabilities and possibly have stronger security implemented which would have been a significant improvement, given that my system is also applied to banking customers.
